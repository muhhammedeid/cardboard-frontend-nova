# خطة التقوية والإصلاح — Nova إلى «تشغيل نظيف جاهز للإنتاج»

**الهدف بسطر واحد:** إغلاق كل ما وجدته تدقيقاتُ real-mode، وتشديد الواجهة والـbackend بحيث يعمل النظام في الإنتاج
بلا فجوة تشغيلية معروفة، مع بوابة نهائية موثّقة.

**التاريخ:** 2026-09-14 · **النطاق المصرّح به:** واجهة Nova + تطبيق `cardboard_management` (الـbackend).
**خارج النطاق (بقرارك):** الواجهة القديمة `frontend/` — لا تُلمس؛ عيوبها تُسلَّم كتقرير فقط.

**مرجع الأدلة:** `docs/REAL-MODE-VERIFICATION.md` · `docs/BACKEND-FINDINGS.md` (BG-01…BG-10 + INF-01).

## المخاطر والضوابط
1. **تعديل الـbackend أثناء مرحلة الاعتماد** → كل تغيير إضافي (لا حذف ولا إعادة تسمية)، مع اختبارات وبرهان حي،
   وبدون أي migrate (لا تغيير مخطط).
2. **بيئة الطرف الخارجي** (bench/MariaDB/Redis يديرها المستخدم) → لا إعادة تشغيل لخدمات؛ التنفيذ عبر الواجهة
   العادية للـbench فقط.
3. **الاقتطاع الصامت في كشف الحساب** → الترقيم يُصاحب حقلَي `total`/`has_more` والواجهة تعرض «عرض المزيد».
